### Builder 패턴

- Builder 패턴이란 ? : 객체 생성 과정을 단계별로 분리하고, 복잡한 객체를 일관성 있고 유연하게 생성할 수 있도록 돕는 생성 디자인 패턴
    - 객체 생성의 복잡성 : 생성자가 너무 많은 매개변수를 요구하거나, 생성 과정이 복잡할 경우
    - 유연한 설정 : 객체 생성 과정에서 다양한 조합이나 조건을 적용해야 할 경우


- 구조 :
  - Builder : 객체를 단계별로 생성하기 위한 인터페이스 또는 추상 클래스
  - Concrete Builder : Builder 인터페이스를 구현하며, 실제 객체를 생성
  - Director (선택적) : 객체 생성 과정을 조율하여 일관성을 유지
  - Product : 최종적으로 생성되는 객체


- 특징 :
  - `단계별 생성` : 객체 생성 과정을 논리적 단계로 나눔
  - `메서드 체이닝 지원` : 단계별 메서드 호출로 직관적이고 간결한 코드 작성 가능
  - `다양한 설정 지원` : 조건에 따라 서로 다른 구성을 가진 객체 생성 가능


- 빌더 패턴이 적합하지 않은 상황 :
  - 객체가 단순한 경우 : 속성이 적고, 설정할 매개변수가 많지 않은 객체는 생성자를 사용하는 것이 더 효율적
  - 객체 구조가 자주 바뀌는 경우 : 새로운 속성이 자주 추가되거나 삭제된다면, 빌더 클래스를 지속적으로 업데이트해야 하므로 유지보수 비용이 증가함 
  - 성능이 중요한 경우 : 빌더 패턴의 단계적 생성 과정이 불필요한 오버헤드가 될 수 있음
