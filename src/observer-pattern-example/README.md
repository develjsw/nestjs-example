### 옵저버 패턴 ( Observer Pattern )

- 옵저버 패턴이란 ? :
  - 객체 간의 일대다 관계를 정의하여, 한 객체(주체, Subject)의 상태 변화가 발생했을 때, 이를 구독(Subscribe)하고 있는 다른 객체들(Observer)에게 자동으로 알림을 보내는 디자인 패턴을 말함
  - 주로 이벤트 기반 시스템이나 Pub/Sub(발행/구독) 모델을 구현하는 데 사용


- 핵심 구성 요소 :
  1. 주체 ( Subject )
     - 관찰되는 대상이며, 상태의 변경이 발생할 때 옵저버들에게 알림을 전송함
     - 옵저버를 등록(Attach)하거나 제거(Detach)하는 메서드를 가짐
  2. 옵저버 ( Observer )
     - 주체를 구독하며, 주체의 상태가 변경될 때 알림을 받고 동작함
     - 주체로부터 알림을 받을 때 호출되는 메서드를 정의함
  3. 구독 관리 ( Subscription )
     - 옵저버와 주체 간의 관계를 관리
     - 옵저버는 주체를 구독하여 상태 변화를 감지하며, 구독 해제를 통해 관계를 종료할 수 있음


- 동작 과정
  1. 옵저버 등록 : 옵저버는 주체의 attach 메서드를 호출하여 등록함
  2. 상태 변화 발생 : 주체의 상태가 변경되면, 주체는 모든 등록된 옵저버들에게 알림을 보냄
  3. 옵저버 반응 : 옵저버는 주체로부터 알림을 받고 자신이 정의한 동작을 실행함


- 장점 :
  - 느슨한 결합 : 주체와 옵저버 간의 의존성이 낮음. 주체는 옵저버가 어떤 객체인지 몰라도 됨
  - 확장성 : 새로운 옵저버를 추가해도 주체의 코드에 변경이 필요 없음
  - 실시간 반응성 : 상태 변경에 따라 자동으로 업데이트를 반영할 수 있음


- 단점 : 
  - 복잡성 증가 : 등록된 옵저버가 많아질수록 관계 관리가 복잡해지고, 디버깅이 어려워질 수 있음
  - 성능 문제 : 상태 변경 시 모든 옵저버에게 알림을 전송하므로, 옵저버 수에 따라 성능 저하가 발생할 수 있음
  - 메모리 누수 위험 : 주체와 옵저버 간의 순환 참조로 인해 옵저버가 제거되지 않고 남아 메모리 누수가 발생할 수 있음. 이를 방지하기 위해 구독 해제를 명시적으로 처리해야 함
