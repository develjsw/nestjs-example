### 전략 패턴 ( Strategy Pattern )

- 전략 패턴이란 ? :
  - 여러 알고리즘 ( 전략 ) 을 정의하고, 런타임에 해당 알고리즘을 동적으로 선택할 수 있도록 설계된 객체지향 디자인 패턴
  - 알고리즘을 교체하더라도 클라이언트 코드에 영향을 주지 않도록 설계


- 구조 :
  - `Strategy ( 전략 인터페이스 )` : 실행 가능한 동작 ( 알고리즘 ) 의 공통 인터페이스를 정의
  - `ConcreteStrategy ( 구체적 전략 )` : Strategy 인터페이스를 구현하는 다양한 알고리즘
  - `Context ( 문맥 )` : 클라이언트와 전략 객체 간의 연결을 담당하며, 선택된 Strategy 실행


- 특징 :
  - 행동 캡슐화 : 알고리즘을 인터페이스 뒤에 숨겨, 클라이언트가 세부 구현을 알 필요 없게함
  - 행동 변경 가능 : 실행 중 ( 런타임 ) 에 전략을 동적으로 변경할 수 있어 유연성이 높음


- 구조 다이어그램 :
  ~~~
  Client → Context → Strategy Interface → ConcreteStrategyA
                                        → ConcreteStrategyB ( 선택 )
                                        → ConcreteStrategyC
  ~~~
  
- 장/단점 : 
  - 장점
    - `알고리즘 캡슐화` : 클라이언트는 구체적인 구현을 몰라도 인터페이스를 통해 알고리즘을 사용 가능
    - `코드 확장성` : 새로운 전략을 추가해도 기존 코드에 영향을 주지 않음 ( Open Closed Principle )
    - `동적 선택` : 실행 중에 전략을 변경할 수 있어 유연성이 높음
    - 유닛 테스트 용이 : 전략을 독립적으로 구현했기 때문에 단위 테스트가 간단해짐
  - 단점
    - 복잡성 증가 : 다양한 전략을 관리하기 위해 클래스와 컨텍스트가 많아지면 코드 구조가 복잡해질 수 있음
    - 많은 객체 생성 : 각 전략이 별도의 클래스로 구현되기 때문에 객체 수가 늘어날 수 있음
    - 단순한 경우 불필요한 오버헤드 발생 : 간단한 로직에 적용하면 복잡도를 불필요하게 증가시킬 수 있음
  

- 객체지향적 패턴으로서의 적합성 : 
  - 단일 책임 원칙 ( SRP ) : 각 전략은 하나의 동작 ( 알고리즘 ) 만 처리
  - 개방-폐쇄 원칙 ( OCP ) : 새로운 전략을 추가하더라도 기존 코드를 수정할 필요 없음
  - 의존성 역전 원칙 ( DIP ) : 컨텍스트는 전략 인터페이스에 의존하며, 구체적 구현에는 의존하지 않음
  - 코드 재사용성 증가 : 각각의 전략은 독립적으로 설계되어 다양한 Context에서 재사용 가능
